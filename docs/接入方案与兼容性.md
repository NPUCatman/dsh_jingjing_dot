# 微信接入方案与兼容性

核实日期：2026-10-24。

## 选择的接入方式

项目使用 Windows 桌面微信的 UI Automation 界面自动化，连接用户自己已登录的微信小号，再将符合配置条件的文本交给 DeepSeek API。微信接入依赖上游 [Hello-Mr-Crab/pywechat](https://github.com/Hello-Mr-Crab/pywechat) 中面向微信 4.1 系列的 `pyweixin` 模块。

安装包名是 **`pywechat127`**，导入模块名是 **`pyweixin`**。不要执行 `pip install pyweixin`：PyPI 上这个同名项目是另一份 0.1.0 旧包，并非本项目使用的依赖。上游的安装与包结构见 [QuickStart.md](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/QuickStart.md)；包元数据可核对 [pywechat127](https://pypi.org/pypi/pywechat127/json) 与 [pyweixin](https://pypi.org/pypi/pyweixin/json)。

准备阶段采用的上游固定提交为：

```text
8589baa049bb91d3a500602c167f07b2f8397a13
```

该提交使用 `src/` 下的安装工程，依赖地址为：

```text

```

选择固定提交是为了让安装结果与已查看的源码一致。核实时 PyPI 的 `pywechat127==1.9.8` 上传于 2026-06-10，GitHub 主分支仍沿用相同包版本号，但源码已有后续修改。

## 版本与账号条件

上游 [README](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/README.md) 声明 `pyweixin` 支持微信 4.1.6+、Python 3.10+；本项目准备使用 64 位 Windows 与 Python。源码中也已有针对微信 4.1.15.11 的说明，但这些声明不代表逐个补丁版本均已验证。

本机发现微信 4.1.15.56 和旧版 3.9.12.55 的安装信息。**本项目尚未在本机微信 4.1.15.56 上完成登录后收发消息实测**，因此当前交付是准备好的程序与验证步骤。接入应先使用 4.1 客户端进行检查，不能仅凭安装版本号判定机器人已可用。

上游 [Weixin4.0.md](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/Weixin4.0.md) 明确说明：微信更新后，部分账号不再暴露完整 UI 树；通过讲述人启用 UI 树的方法已失效，部分使用过无障碍模式的账号仍可读取控件。是否可用取决于账号和当前客户端实际提供的控件。

因此，首次接入必须先检查消息列表和输入框是否可见。当前登录账号只能读取 Qt 外壳，不能使用 UIA 接入；无需反复尝试登录。项目另提供 `run --adapter ocr` 本地 OCR 试验接入，不修改注册表、不注入、不绕过登录。

## 本地 OCR 试验接入

`ocr-setup` 在截图中校准消息区和文字输入区；`ocr-probe`、`ocr-watch` 只做本地识别，不调用 DeepSeek、不发微信消息。截图仅留在内存，校准坐标及背景色保存在被 Git 忽略的 `data/ocr-calibration.json`。

接入只绑定精确标题、`Weixin.exe` 进程及校准尺寸一致的独立窗口，采用 PMv2 物理像素坐标。锁屏、最小化、遮挡、失焦或尺寸变化时停止。消息区先定位灰色入站/绿色出站气泡，再局部识别；昵称、居中时间及可见图片通常被排除，但图像规则无法保证所有带文字图片均可区分。

首次需要至少一条完整文字气泡、连续两帧一致才建立基线；后续依据有序可见序列的重叠确认新增入站文字。识别恢复、历史切页或失去锚点时优先跳过而非补发，因此会漏掉部分新消息。不要运行期间滚动历史；新旧消息画面在某些情况下不可区分。

输出先限制为短纯文字，加入“小鲸鱼：”前缀。发送前用空白像素检查保护草稿，点击后再检查，然后通过 Unicode 键盘输入单行文字。仅在本地 OCR 核对输入内容一致时按 Enter；发送后输入框仍非空或结果不明确时停止，保留草稿并且不重试。此过程不是微信送达回执，运行期间需要让出鼠标键盘。

本机已验证真实独立聊天窗口截图、文字识别及空白输入区域。自动点击、输入、Enter 发送和真实新消息触发仍需用户按 README 的预览、正式运行顺序验证；离线测试不证明端到端收发成功。

官方 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin) 是另一种 Bot 授权路线，但当前插件声明仅支持 `direct`。其 `group_id` 协议字段不能证明支持群聊，也未证明能接管普通小号现有好友和群，所以没有替换本项目目标。

## 本项目如何监听与回复

适配层只处理配置中指定的独立聊天窗口。它读取普通模式的 `ListItem` 消息元素，以 UIA `runtime_id` 在当前运行中去重，并在启动时记录窗口里已有消息作为基线，避免将打开窗口前的聊天记录重新提交给模型或补发回复。`runtime_id` 是运行时控件标识，不是微信提供的永久消息 ID。

当前仅将 `mmui::ChatTextItemView` 作为文本消息。消息列表和编辑框的定位依据来自上游 [Uielements.py](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/src/pyweixin/Uielements.py)，独立窗口打开逻辑参考 [WeChatTools.py](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/src/pyweixin/WeChatTools.py)。

识别自己发送的消息使用上游 `Tools.is_my_bubble`。这个方法通过截图中头像和气泡的像素位置作判断，需要对应窗口可见、处于适合截图与交互的前台状态。它不是微信提供的发送者身份字段，应在首次测试时同时验证“收到好友消息会回复”和“机器人自己的回复不会再次触发回复”。遮挡、最小化、锁屏、主题或界面变化都可能影响结果。

微信自动化会使用鼠标、键盘与窗口焦点。启动后需要保留可交互的 Windows 桌面，并避免同时手动切换或操作这些聊天窗口。

## 群聊触发与记忆边界

当前普通消息列表接口无法稳定获得群成员发送者标识。上游 [utils.py](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/src/pyweixin/utils.py) 的群消息解析依赖多选状态，或同时采集带姓名与不带姓名的两份文本；本项目的常驻监听没有采用这种切换方式。

因此，**每个指定群使用该群共享的短期对话记忆，不承诺按群成员隔离上下文**。不同指定群之间的记忆分别保存；同群内不同成员的触发消息可能进入同一段上下文。

群内建议使用 **`/鲸鲸` 前缀**触发回复。配置的 `@昵称` 只检查消息开头是否出现相应文本，不代表读取到了微信真实的 mention 元数据；手动输入相同文本也可能触发。需要明确、可重复的测试时，应优先使用 `/鲸鲸`。

## 依赖许可与紧急停止

固定提交的 [LICENSE](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/LICENSE) 标题为 GNU Lesser General Public License，版本 2.1，正文以 `pywechat library` 指代库。运行和导入库不需要购买上游激活码；若以后修改、复制或分发该库，应保留许可、来源及对应的分发义务。项目自身代码与上游依赖应分别标明来源。

上游 [WeChatAuto.py](https://github.com/Hello-Mr-Crab/pywechat/blob/8589baa049bb91d3a500602c167f07b2f8397a13/src/pyweixin/WeChatAuto.py#L90) 在导入时执行 `pyautogui.FAILSAFE = False`。本项目适配层应在加载依赖后恢复为 `True`，保留 PyAutoGUI 的鼠标移至屏幕角落停止机制；也可以在运行终端按 `Ctrl+C` 停止程序。

## 未作为默认依赖的方案

核实时 [wxauto4 官方安装页](https://docs.wxauto.org/docs/install.html) 标明免费版最高支持微信 4.1.8.107，而监听相关接口在 [WeChat 类文档](https://docs.wxauto.org/docs/class/WeChat.html) 中标记为 Plus 专用，因此不能将免费版直接视为本机 4.1.15 的已验证替代方案。

[WeChatFerry](https://github.com/lich0821/WeChatFerry) 已于 2026-07-10 归档，README 的适配版本停留在微信 3.9.12.51，且采用 hook / DLL 注入；[itchat](https://pypi.org/pypi/itchat/json) 最新 PyPI 发布为 2017 年的 1.3.10，依赖网页微信。这两条路线均未作为本项目的默认接入方式。
